# Plan: ot00.1 — Split claude_code into install-only + claude_code_config

Status: pending approval

## Goal

Split role `claude_code` into install-only `claude_code` plus new
`claude_code_config` holding all `~/.claude` global config. End state of
basic/desktop hosts identical to today; host with only `claude_code` has the
binary and NO `~/.claude` opinionation. Unblocks ot00.3.

## Acceptance criteria

- A1 basic/desktop end state equivalent to pre-split.
- A2 claude_code-only host has binary + PATH, no `~/.claude`.
- A3 both molecule tests pass, idempotent re-run zero changes.
- A4 version pin stays in `claude_code` defaults.
- A5 version-update wiring unchanged.
- A6 config role declares `claude_code` meta-dep + explicit play ordering.
- A7 config role has own full-lifecycle Molecule scenario.

## Decision (feature-scoped, not an ADR)

Two roles; `claude_code_config` declares `[rtk, nodejs, ai_agent_workspace,
claude_code]` in meta AND explicit play ordering. Alternatives rejected:
ordering-only (fails Principle II decision test — unguarded `claude plugin`/
`mcp` calls hard-need the binary); single role + flag (YAGNI, issue mandates
two roles). Consequence: dependency edges duplicated across meta/playbook/
converge — accepted DRY tension per dependency doc. Rationale lives in issue
ot00.1 and the split role DESIGN docs; no ADR created.

## Process requirements

Feature branch from main; `commit` skill per commit; user review after each
commit; `fix-problem` on obstacles; `molecule-testing` for scenarios;
`review-documentation-here` then `format-markdown` at close.
